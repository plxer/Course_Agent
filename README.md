# 天津大学《计算机网络》课程数智化平台

面向《计算机网络》的智能助学站点：课本伴读、视频学习、章节习题与对话答疑等；对话与检索由大模型与课程知识库驱动。

## 项目说明

本仓库由开源项目 **[Yuxi-Know（语析）](https://github.com/xerrors/Yuxi-Know)** 二次开发而来，**定位与功能已与原版通用「智能体平台」不同**：此处实现 **天津大学《计算机网络》课程数智化平台** 的教学场景。

**从 Yuxi-Know 沿用的部分（底座）：**

- **Docker 与编排**：`docker-compose.yml`、`docker-compose.prod.yml` 及容器化运行方式（API、前端开发服务、PostgreSQL、Neo4j、Milvus、MinIO 等）。
- **底层 Web 架构**：后端 **FastAPI**，前端 **Vue 3 + Vite + Ant Design Vue**（`server/`、`web/` 目录层次与请求路由习惯延续上游）。
- **数据与中间件栈**：关系库 **PostgreSQL**、向量检索 **Milvus**、图数据库 **Neo4j**、对象存储 **MinIO**、鉴权与会话等与上游一致的部署假设（具体以 `.env` 与 Compose 为准）。

**在本仓库中扩展或替换的部分：**

- **入口与路由**：默认进入 **课程区**（首页重定向至 **`/course`**，登录成功亦默认至此）；提供 **课本伴读、视频、习题、对话、使用指南** 等页面；管理员仍可通过 **知识库 / 图谱 / 智能体管理** 等原有路径维护平台。
- **后端**：增加 **课程 API**（课本与 PDF、章节信息、伴读与对话流、视频与字幕、习题与错题等），数据落在 PostgreSQL 的课程相关表中。
- **前端**：课程界面、登录注册等品牌与交互；登录背景可在后台「组织信息」中配置。
- **课程资源**：**`knowledgebase/books/`** 存放课本 PDF；**`knowledgebase/videos/`** 存放视频及字幕、摘要等；目录根可通过环境变量 **`KNOWLEDGEBASE_DIR`** 配置。

课程能力与 Yuxi-Know 自带的 RAG、知识库、图谱、智能体 **共用同一套服务与中间件**，在此基础上增加面向章节与教材的业务接口与页面。

## 课程功能概览

| 模块 | 说明 |
|------|------|
| 课本伴读 | 基于课程 PDF 的划选、翻译与答疑 |
| 视频学习 | 章节视频与字幕、摘要等 |
| 习题练习 | 按章节 / 知识点组卷与作答 |
| 智能对话 | 绑定课程知识库的问答与智能体对话 |

实际可用功能取决于是否配置课本、视频与大模型 API（环境变量与 `.env`）。

## 技术栈详解

以下为各组件在本平台中的**分工**（依赖版本见 `pyproject.toml`、`web/package.json`）。

### 前端（`web/`）

| 技术 | 作用 |
|------|------|
| **Vue 3** | 单页应用：课程页、登录与注册、管理端界面。 |
| **Vue Router** | 路由与权限（登录态、管理员）；默认进入课程首页。 |
| **Vite** | 开发与构建前端资源。 |
| **Ant Design Vue** | 界面组件（表单、布局、按钮等）。 |
| **Pinia** | 全局状态：用户信息、系统品牌配置、对话相关状态等。 |

浏览器通过 **`/api`** 调用后端；智能对话等能力使用 **流式响应** 推送内容。

### 后端 API（`server/`、`src/`）

| 技术 | 作用 |
|------|------|
| **FastAPI** | 提供 REST 与流式接口，处理鉴权、参数校验与业务逻辑。 |
| **Uvicorn** | ASGI 服务进程，运行 FastAPI 应用。 |
| **SQLAlchemy（异步）** | 访问 **PostgreSQL**，读写业务数据。 |

课程相关接口集中在 **`/api/course`**，其余为系统设置、知识库、智能体管理等。

### PostgreSQL（关系型数据库）

存储**账号、权限、会话与业务记录**等结构化数据，主要包括：

- **用户与组织**：账号、角色、部门、登录安全与习题积分等。
- **对话与消息**：会话列表、每条消息内容、工具调用记录及统计，用于历史查看与管理。
- **平台配置**：智能体展示配置、**MCP 服务**连接信息、异步任务记录等。
- **课程相关**：课本伴读进度、习题作答与错题、用户反馈等。

知识库的**文件条目与状态**也多存在此库；**文件实体**通常放在 MinIO（见下）。

### MinIO（对象存储）

与数据库分工：**库存索引与关系，对象库存文件字节**。典型用途包括：知识库解析生成的 **Markdown**、上传文件的副本、对话**附件**等；数据库中保存对应的存储路径或访问地址。部署中与 Milvus 配套的 MinIO 还可能承担向量引擎的内部存储，由运维区分桶与权限。

### Milvus（向量数据库）

将知识库文档切片后的 **向量** 存入其中，检索时按 **语义相似度** 召回片段，支撑 **RAG（检索增强生成）**。课程对话绑定 Milvus 知识库时，课本相关内容通过该通道检索。

### Neo4j（图数据库）

存储 **知识图谱**：文档抽取的实体与关系（如 LightRAG）、或手动导入的三元组，用于图谱可视化及智能体的图查询。**与 Milvus 的关系**：Milvus 侧重「一段话相似什么」，Neo4j 侧重「实体之间如何连接」。

### SQLite（配合 LangGraph）

智能体运行时使用 **SQLite** 保存 **LangGraph 运行时 checkpoint**（多轮对话中间状态），便于断点续跑。用户在界面里看到的**对话列表与消息回放**仍主要由 **PostgreSQL** 承担。

### LangChain

连接 **大模型与 Embedding**、封装 **检索 / 知识库 / MCP 工具** 等，供上层智能体调用；相当于「模型与工具」的中间层，不是另一种数据库。

### LangGraph

将智能体实现为 **可持久化的状态图**：编排多轮对话、工具调用与中间件（如重试、注入知识库），并以 **流式** 方式把模型输出交给前端。课程中的对话接口在后端调用这些智能体图完成推理。

### 其他

| 技术 | 作用 |
|------|------|
| **LightRAG** | 兼顾图谱与向量的增强检索管线（图谱部分写入 Neo4j）。 |
| **JWT 等** | 登录鉴权，与用户表配合。 |
| **Docker Compose** | 编排 API、前端开发服务、PostgreSQL、Neo4j、Milvus 及依赖组件；可选 OCR/解析服务见 Compose **profiles**。 |

## 课程资源目录（简要）

- `knowledgebase/books/`：课程 PDF 课本

## 快速开始

```bash
git clone <本仓库 URL>
cd <仓库目录>

# Linux / macOS
./scripts/init.sh

# Windows PowerShell
.\scripts\init.ps1
```

复制并编辑 `.env` 后启动：

```bash
docker compose up --build
```

- 前端开发地址：**http://localhost:5173**  
- API：**http://localhost:5050**  

生产环境可参考 `docker-compose.prod.yml` 与 `docker/nginx/`。仅在本地调试前端时，进入 `web/` 执行 `pnpm install`、`pnpm run dev`，并在 `vite.config.js` 中将 `/api` 代理到后端。
